# TASKS.md — FundReady Mobile Frontend

The build queue for the Expo app. Same rules as `backend/TASKS.md`: **do one task at a time**, top to bottom, finish it (code + verification + docs), check it off, then move on. Acceptance notes are the bar for "done."

Legend: `[ ]` todo · `[x]` done · `[~]` in progress

**Phases are numbered to line up with the backend's.** An `F`-task usually cannot close before the `T`-task it names, because the client cannot show data no endpoint returns. Where the backend is already ahead of the client, that is called out — those are the cheapest tasks in this file.

**What "done" means here.** A green `npx tsc --noEmit` proves almost nothing about this app: every trap in `AGENTS.md` §"Traps that do not fail the build" compiles and typechecks while rendering wrong. A task closes when the screen was **driven in a browser or on a device**, not when it built.

> **Standing caveat on the 2026-08-01 batch (F0.1, F0.2, F1.5–F1.8).** Those closed against `npm run lint`, `npm run typecheck`, 88 Jest tests and a clean `expo export --platform web` — which proves Metro resolves every import and that `/reset-password` is a real route. **None of those screens has been rendered in a browser or pointed at a running backend.** The transport is covered by tests at the `fetch` boundary, so the request shapes are checked against what the API's routers declare; what is *not* checked is the API actually answering them, and nothing about how any of it looks. Run the app against a local backend before trusting the ticks — the rendering half is F0.5's job and F0.5 is still open.

## Phase F0 — App setup

- [x] **F0.1 Scaffold** — Expo SDK 57 / React Native 0.86 / expo-router / NativeWind 4 under `src/`, `@/*` path alias, `.env.example`, developer documentation. *Done when: the layout exists, `npx tsc --noEmit` is clean, and the README tells a new developer how to run the app against the backend.* — closed 2026-08-01. The structure, the alias and `.env.example` (with the correct warning that `EXPO_PUBLIC_*` ships to the device readable) were already there; `README.md` was still the stock `create-expo-app` template, advertising `npm run reset-project` — which moves this entire app aside — and has been replaced with run/env/check instructions that point at `AGENTS.md` for the traps.
- [x] **F0.2 Tooling & CI** — lint, format, type-check and a test runner, all run on every push. *Done when: CI is red on a type error and on a lint error, in a job that actually looks at `frontend/`.* — closed 2026-08-01. Before this, `package.json` had a `lint` script (`expo lint`) with **no ESLint installed and no config**, zero test files, and a root workflow that ran `ruff`/`mypy`/`pytest` only: **no CI job had ever looked at this directory.** Now `eslint.config.js` (flat, on `eslint-config-expo`), `jest.config.js`, 88 tests in `test/`, and a `frontend` job in `/.github/workflows/ci.yml` running `npm ci` → lint → typecheck → test with `working-directory: frontend`. Four things worth knowing:
  - **ESLint found 11 errors on its first ever run**, which is the whole argument for the task. Nine were fixed (three unused imports; `useMemo(upcomingDays, [])` never memoising because the argument was not an inline function; `useRef(new Animated.Value(…)).current` read during render in `score-ring.tsx`, now a lazy `useState`). Two were left with a targeted disable and a written reason: the `PanResponder` handlers in `slider.tsx` read a ref, but only after a gesture starts, and the `setLimit` reset in `dealflow-screen.tsx` — the idiomatic fix there is to key the component on the filter, which changes how parents mount it, and there is no rendering test to catch what that breaks.
  - **`jest-expo` is deliberately not a dependency.** Its peer range wants `@react-native/jest-preset@^0.86.2` while `react-native@0.86.0` pins that package to exactly `0.86.0`, so installing it needs `--legacy-peer-deps` — and then `npm ci` in CI needs it too. A CI that has to be told to ignore a broken dependency graph is not much of a gate. Native modules are mapped to stubs in `test/stubs/` instead, including `expo/virtual/env` (which `babel-preset-expo` injects as untransformed ESM).
  - **The cost of that: there are no component rendering tests.** Every trap in `AGENTS.md` — dropped `className`, two colour utilities on one element, nested `Pressable` — still passes `npm test` while rendering wrong. Jest covers the transport, the gates and the parsing; it does not cover the pixels. That is F0.5's job.
  - **Prettier is installed but is not a gate.** The app predates it by ~80 files at any print width, so `--check` fails everywhere and a repo-wide reformat would bury real changes in whitespace. The CI step is `continue-on-error`. Run `npm run format:write` to take that diff in one commit, then promote it.
  - No `paths:` filter, deliberately: a frontend-only push still runs the backend suite and vice versa. It is slower, but a filtered job that never runs reports success it did not earn.
- [x] **F0.3 Design system** — `theme/tokens.ts` mirroring `tailwind.config.js`, Geist + Geist Mono, the `components/ui/` primitives, `css-interop.ts` registration for non-core components. *Done when: a screen can be built without inventing a colour or a font weight.* — the token/Tailwind duplication is deliberate and documented: Tailwind cannot reach SVG strokes, gradient stops or data-driven colours, so `C` and `band()` exist for those. Two invariants hold and must keep holding: `Txt*` drops its default colour when the caller supplies one (two colour utilities on one element resolve by stylesheet order, not class order — white-on-white), and weight comes from the font family (`font-med`/`font-semi`), never `fontWeight`, because Geist ships one file per weight.
- [x] **F0.4 Navigation & role separation** — `founder/` and `investor/` as **real path segments, not route groups**, each with its own `(tabs)`; `role-guard.tsx`; `index.tsx` as the entry redirect; typed routes on. *Done when: an investor cannot reach a founder route by typing its URL, and the two sides cannot collide on a route name.* — the segment choice is what makes the guard possible: a group would let both sides claim `/profile` and leave the guard with nowhere to bounce to. `lib/routes.ts` casts hrefs once because typed routes emit `/founder/index` while the runtime wants `/founder`.
- [~] **F0.5 UI verification harness** — `scripts/verify-ui.js`, driving both sides end to end through Playwright against installed Edge, asserting on computed styles and rendered text. *Done when: the harness passes against the current app and catches the `AGENTS.md` traps.* — **built (479 lines) but now stale, and it will fail if run today.** It was written against `src/api/mock.ts`, which was deleted in `3925df7`; four of its steps still assume mock behaviour that no longer exists ("the mock approves on a timer", "the mock answers from the founder's own numbers — 1450/320 = 4.5:1", and the two comments about resetting mock module state). Everything past sign-in now hits `not_implemented`. **Decide before repairing it:** either it re-targets a live local backend (real value, needs the API running and a seeded account), or it narrows to auth + the render traps + the `Unavailable` states and stops claiming to cover the product. The second is honest and cheap; the first is what actually protects the release.

## Phase F1 — Backend seam & authentication

- [x] **F1.1 API seam** — `api/contract.ts` as the one interface the app knows, `api/index.ts` choosing the implementation. *Done when: no screen imports `fetch`, and swapping the implementation touches no screen.* — the mock and its 24-company seed dataset were **deliberately deleted** (`3925df7`), not left switchable. The reason is worth keeping: a mock that renders plausible numbers is indistinguishable, on screen, from a working feature, and this app is far enough ahead of the backend that the difference matters. Everything unbuilt now throws `not_implemented` and `components/unavailable.tsx` renders it as a dashed **NOT BUILT YET** panel — visually distinct from the red **COULD NOT LOAD** it shows for a real failure.
- [x] **F1.2 HTTP transport** — `api/http.ts`: base-URL resolution, the backend's error envelope mapped to `ApiFailure` codes, 401 → refresh → retry, token pair at rest. *Done when: a 401 transparently refreshes once, and a replayed refresh cannot be triggered by two screens loading at once.* — three calls worth knowing. **The refresh is single-flight** (`refreshing ??=`): the server treats a second presentation of a rotated refresh token as theft and revokes the whole family, so two concurrent 401s starting two exchanges would log the user out — the client's concurrency is a security property here, not a performance one. **The new pair is stored before it is returned**, because the old one is already spent and losing the new one locks the account out until a fresh login. **The base URL is derived from whatever served the bundle** (`8f59f56`) rather than baked in: a phone cannot reach `localhost`, and DHCP moves the LAN address, so `EXPO_PUBLIC_API_URL` wins when set and the dev-server host is inferred otherwise — with a separate `globalThis.location` branch for web, where `hostUri` is never populated.
- [x] **F1.3 Sign-up, sign-in, sign-out** — `sign-up.tsx`, `sign-in.tsx`, the founder company-domain rule, names collected and sent. *Done when: a founder on a consumer mailbox is refused with a reason, and a registered account can sign in and out against the live API.* — **no consumer social login; Google and LinkedIn were removed deliberately.** `domain/email.ts` works by blocklist rather than by trying to prove a domain is corporate: a false reject turns a real founder away, which costs more than letting an unusual domain through, and the company is verified properly later. The client check is convenience — the server is the control, and as of backend T1.4a it enforces the same rule. **Registration sends `first_name`/`last_name` again as of `3c1fcc3`**; the 422 that broke every mobile registration between 2026-07-30 and that commit is closed (`backend/TASKS.md` still carries it as open — see the follow-ups below). Registration answers 202 with no tokens and answers identically whether or not the address was taken, so `signUp` logs in immediately afterwards: that round trip is what proves an account exists.
- [x] **F1.4 Two-factor login** — the `mfa_required` branch, `MfaRequired`, `mfa.tsx`. *Done when: a login that needs a second factor lands on the code screen and the exchanged pair is a real session.* — the shape matters: login returns `status`, and **`tokens` is null on the MFA path** while a short-lived `mfa_token` carries the challenge. Branching on `status` rather than assuming `tokens` is what stops a null dereference becoming a silent signed-out state. Admins are refused a session in the app entirely (`sessionFrom` throws `forbidden` and clears the tokens) — the console is the admin surface, per backend `AUTH.md` §9.
- [x] **F1.5 Email verification** — `verify-email.tsx`. *Done when: a founder can confirm their address from the emailed link without typing anything, and the screen notices the moment the server marks it confirmed.* — closed 2026-08-01 by F1.7. The state half was already real: `emailVerified` is read off `/v1/users/me` on every load and on focus, never cached, so the screen agrees with the server the instant it changes. What was missing was the link — the screen asked the user to *paste a token into a text field*. It now reads `?token=`, submits once on arrival behind a ref guard (these are single-use; a re-render spending the token again would fail the second attempt), hides the paste field when the link supplied one, and keeps it when it did not. **The screen now works signed out**, which it did not before: whoever follows the link may not be signed in on that device, the endpoint takes no authorization, and a `confirmedHere` flag renders the result when there is no account to re-read. Two things still open, both backend-side: `resendVerificationEmail` throws `not_implemented` because no resend endpoint exists, and `https://` links do not open the app until F5.5 configures Universal/App Links.
- [x] **F1.6 Password reset** — `forgot-password.tsx` + `reset-password.tsx`. *Done when: a user can complete a reset end to end, from the email to a new password to a working login.* — closed 2026-08-01. The missing half was not on the contract at all: nothing took a token plus a new password, so a founder who requested a reset reached a dead end while a working backend endpoint sat unused since 2026-07-30. Added `resetPassword(token, password)` to `FundMeApi`, `/v1/auth/password-reset/confirm` in the transport, and the screen. Design calls:
  - **The local token pair is dropped on success.** The server has just revoked every refresh token and invalidated every access token it issued, so what the device holds is dead — and if a *different* person completed the reset, keeping it would leave a live-looking session on a device they now control. A *failed* reset changes nothing server-side, so the session is deliberately left alone; both are asserted.
  - **"Signed out everywhere" is stated, not implied.** Otherwise the other device dropping to the sign-in screen reads as a fault rather than as the point.
  - The password rule moved out of `sign-up.tsx` into `domain/password.ts`, shared by both screens. Two screens now mint passwords, and a client that lets through something the server refuses turns a typo into an unexplained `422`. No composition rule, deliberately — length is the defence.
  - Fixed while here: `forgot-password.tsx` told the user the link expires in 30 minutes. The backend's `PASSWORD_RESET_TTL` is an hour.
- [x] **F1.7 Deep links** — consume the `APP_LINK_BASE_URL` links: verification token, reset token, signed-out fallback. *Done when: tapping the link in a real email opens the app on the right screen with the token already applied, and the same link opened by a signed-out user still works.* — closed 2026-08-01. **There is deliberately no URL parser.** expo-router's own linking already resolves `sacifundme://reset-password?token=x`, the Expo Go `exp://…/--/…` form and the plain web URL onto the same route with the same search params; a hand-rolled parser would be a second, worse implementation of something already in the bundle. What was left is reading one parameter safely, which is `lib/deep-link.ts`: array-valued repeats, the trailing newline a wrapped URL picks up, and `?token=` (empty) returning null rather than posting nothing and earning a generic "this link is invalid". **The two route segments are now a contract with the server** — `verify-email` and `reset-password` — and renaming either breaks every link already in an inbox; `lib/routes.ts` says so. **Still open: `https://` links do not open the app.** Universal Links (`associatedDomains`) and App Links (`intentFilters`) are not configured, so `APP_LINK_BASE_URL` must be the custom scheme to reach a phone. That is F5.5, and it is why both screens keep a paste-the-code fallback.
- [x] **F1.8 Startup profile** — wire `getProfile`/profile editing to the real `T1.4` endpoints. *Done when: a founder's profile round-trips to the server and survives reinstalling the app.* — closed 2026-08-01. `getProfile`, `saveProfile` (create-then-update, with the 409 race handled: two devices both read "none yet", both `POST`, and the loser must update the profile that now exists rather than report a failure), and `getFounderAccount` now preferring the **stored** company name over the guess from the email domain. Onboarding reads the saved profile back on mount, so four screens of typing survive being abandoned halfway. **The important finding is the shape mismatch**, and it needs a product decision:
  - **Six of the form's fifteen answers have nowhere to go on the server.** `growth`, `tam`, `margin`, `ltv` and `technical` have no field in `modules/intake/fields.py` at all; `Bootstrapped` is not one of the server's stages. The form came from the design prototype and the field list was written independently.
  - **They are reported, never swallowed.** `toWireProfile` returns them in `unmapped` with a reason each, and the results screen renders a **NOT SAVED YET** panel listing them. Dropping them silently is the worse failure: the founder types a number, the screen accepts it, and later the audit is silent about it with nothing anywhere explaining why.
  - **Nothing is derived.** Revenue × (1 − margin) *would* yield `cost_of_revenue_minor`, and it is tempting, but a figure the client computed and labelled `source: founder` is a fabricated input to an audit that has to cite its evidence (`CLAUDE.md` §5). If those derivations are wanted they belong on the server, marked as derived. A test asserts the client does not do it.
  - **Money needs a currency, and the currency comes from the country.** The form asks for free text ("Lagos, Nigeria") and the server wants ISO 3166-1 alpha-2 plus ISO 4217. An unrecognised location is reported unmapped rather than guessed — a wrong country silently selects the wrong benchmark set and the founder is scored against the wrong market with no sign of it — and money is withheld entirely rather than stored as an integer whose unit nobody knows. Zero-decimal currencies are handled: multiplying yen by 100 would overstate revenue 100-fold.
  - Expect this file to move: `fields.py` is flagged **provisional** in the backend's own task list pending the missing spec.
- [ ] **F1.9 Document upload** — deck and financials to R2 through the backend's signed URLs, with progress and failure states. *Done when: a real file uploads from a device and comes back down through an expiring URL.* — the onboarding step already picks a file with `expo-document-picker` and holds a filename. Blocked on backend T1.5, which is built but has **never written a byte** (no R2 buckets, no keys). Client-side notes for when it unblocks: the presigned PUT cannot enforce size (the server checks afterwards with `head_object` and deletes anything oversized), so the **client must enforce the limit before uploading** or the user watches a long upload get silently discarded; and the declared content type is pinned into the signature, so it has to match the bytes exactly.
- [ ] **F1.10 Company verification** — `founder/verify.tsx` against a real endpoint. *Done when: a submitted registration document moves the account to `in_review` server-side and the screen reflects it.* — screen is built (235 lines, including the upload); `submitCompanyRegistration` throws `notYet('T1.4')`. **No backend task covers company-registration verification** — T1.4a supplies the company *name* from the domain, which is not the same thing, and `kyc_status` is investor identity (the client is careful not to confuse the two). Raise it as backend scope before building further here.

## Phase F2 — Audit surface

- [~] **F2.1 Assessment intake** — the four-step onboarding form, per-step validation, resumable. *Done when: a complete profile is submitted to the audit engine and the app stops scoring anything itself.* — **the form is done** (`(onboarding)/onboarding.tsx`, `isStepValid` gating each step) and, since F1.8, it is **resumable and persisted**: `load()` reads the stored profile back on mount, and `submit()` saves before scoring so answers survive even though the audit engine does not exist.
