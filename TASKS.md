## Phase 2 — Audit engine

- [ ] **T2.1 AI client** — `ai/client.py` with model tiering, structured-output validation, retry-on-invalid, prompt versioning, injection guards. *Done when: a call returns schema-valid JSON or fails cleanly.*
- [x] **T2.2 Finance module** — `audit/finance.py` deterministic calculations + currency normalization. *Done when: unit tests cover the core ratios; no LLM involved.* — **taken before T2.1** because it is the only Phase 2 task with no external dependency: `ANTHROPIC_API_KEY` is unset, so T2.1 would land `[~]` like T1.2a and T1.5, and the rubric (T2.6) scores against these figures anyway. 49 tests, no database, no fixtures, no network. Two design calls worth knowing: **"cannot be computed" is `None` plus a named reason, never a zero** — a `0.0` margin for a pre-revenue company would be scored as a real 0% margin, which is the false verdict `CLAUDE.md` §5 forbids; and **`Decimal` throughout**, so T2.9's same-input-same-score holds without float drift. **No currency conversion, deliberately** — benchmarks are region-keyed and every ratio that drives scoring is dimensionless, so conversion would buy nothing and cost an FX dependency plus stale-rate risk. Cross-region investor comparison (T4.3) is where that decision belongs. `run_rate_vs_trailing_percent` is **not** a growth rate and is named so it cannot be mistaken for one — a real one needs monthly history the profile does not carry (a `fields.py` change, not a calculation).
- [x] **T2.3 Benchmark KB** — model + admin CRUD keyed by sector × stage × metric × region with source/date. *Done when: benchmarks can be created and queried.* — quartile bands (p25/p50/p75), not a single median: a rubric asking "is this good" needs a spread, and adding them later would migrate a table already holding curated rows. `source` and `as_of_date` are NOT NULL because a verdict cites its evidence and benchmarks go stale. **The metric vocabulary is `FinancialSummary` field names**, with a test asserting the correspondence — a benchmark keyed to a name `finance.py` does not emit returns nothing at lookup, and "not stored" is indistinguishable from "renamed field". Absolute-currency figures (`net_burn_minor`, `annual_run_rate_minor`) are excluded: no FX conversion means a naira burn has no comparison against a dollar band. **The fallback chain is the feature**, not an edge case — sector is free text (D11) so exact matches often miss, and lookup returns `MatchQuality` alongside the band so the rubric knows whether it compared against a Nigerian fintech median or an all-sectors global one. Deliberately not fuzzy: pgvector is available and a similarity score deciding which benchmark judges a founder would be neither reviewable nor reproducible (D9). Retire, never delete — an AuditRun cites what it scored against. Migration `0008` verified up and down, applied to **both** Neon branches. 38 tests.
  - **Known boundary exception:** `audit/benchmarks.py` imports `Stage` from `intake/fields.py`, which `ARCHITECTURE.md` §3 otherwise forbids. Redeclaring the enum would drift the first time a stage is added, and a benchmark keyed to a stage the profile cannot hold is worse than the import. **The tidy fix is promoting `Stage` to `core` alongside `Role`** — not done here because it touches tested T1.4 code and belongs in its own change.
- [ ] **T2.4 Extraction stage** — documents → Startup Profile fields with source/confidence and missing-field flags. *Done when: a sample deck+financials populate the profile.*
- [ ] **T2.5 Consistency check** — cross-document contradiction detection → `dataIntegrityScore` + contradiction list. *Done when: a planted contradiction is flagged.* — **must also carry unit-scale plausibility**, which T2.2a proved cannot live at the field boundary: `monthly_churn_percent: 0.02` meaning 2% is indistinguishable from a genuine 0.02% by range alone, and it yields an LTV **100x too high**. Only a cross-field check — churn against customer count and revenue, revenue against run rate — can see it. Same class of error as major units submitted where minor units belong.
- [ ] **T2.6 Rubric v1** — universal core + adaptive layer; saleability rubric; explicit criteria; versioned. *Done when: `rubric/v1` scores a profile with citations.*
- [ ] **T2.7 Scoring + synthesis** — dimensional scoring → verdicts (fundable/saleable) + founder report + action plan; provisional on thin data. *Done when: a full report is produced and grounded in stages 2.4–2.6.*
- [ ] **T2.8 AuditRun persistence** — model, `rubricVersion`, embeddings; `run_audit` background job + queue; status endpoint. *Done when: submitting a profile runs an async audit and status is pollable.*
- [ ] **T2.9 Golden-set harness** — evaluate audits against hand-scored companies; consistency test (same input → same score). *Done when: an eval report is produced and repeatable.*
